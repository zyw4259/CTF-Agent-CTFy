## 待修复与验收

以下行为在接收审查时通过离线模拟复现，原始源码导入没有修复这些问题：

1. **动态执行开关：** `attachment_tools.execute(..., action='local_gdb', allow_execution=False)` 仍调用 `local_binary.gdb_run`，规划器也只根据 GDB 是否安装暴露动作。需要检查权限开关，并验证不可信附件的执行隔离。
2. **AWD flag 来源：** `flags_from_steps` 扫描整个工具结果，包括 TCP `sent` 字段。自己发送 `flag{probe_only}`、对手没有返回 flag 时仍提取出该字符串。应只从实际响应内容提取并验证对手主机。
3. **Defence 源码传递：** `solve_defence` 获取源码后只把文件名加入 note，没有把正文交给分析器。应传入代码附件或验证独立的二次读取路径；补丁接口受理后还需要确认平台最终验证结果。
4. **v2 dry-run：** `main` 在 dry-run 分支不读取任务，v2 输入也返回 schema_version 3。需要对齐平台契约。

合并验收需要涵盖 qa、instance（含分阶段解锁）、engagement、defence、AWD，检查提交拒绝/超时、比赛截止时间、补丁验证结果和非 root 挂载目录写权限。重新构建镜像时还需核实 `push-ctfy.ps1` 中 registry 命名空间的归属。
